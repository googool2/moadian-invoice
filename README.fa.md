# moadian-invoice

یک Agent Skill که به Claude کمک می‌کند صورتحساب الکترونیکی **سامانه مودیان** (سازمان امور مالیاتی، tp.tax.gov.ir) را بسازد، اعتبارسنجی کند، فیلدهایش را توضیح دهد و خطاهای سامانه را تفسیر کند.
[English](README.md)

## مسئله

صورتحساب مودیان یک JSON با کلیدهای کوتاه و رمزی است: `inty`، `inp`، `ins`، `tob`، `tprdis`، `tadis`، `tvam`، `tbill`، `setm`، `cap`، `insp` و … . مدل بدون راهنما معنی این‌ها را حدس می‌زند. حدس‌هایش معمولاً باورپذیرند ولی غلط. نمونه‌ها:

- `dis` تخفیف کل ردیف است، نه تخفیف هر واحد.
- `cap` و `insp` بدون مالیات بر ارزش افزوده‌اند و فقط برای تسویهٔ نقدی/نسیه به کار می‌روند.
- `tob` برابر ۱ یعنی شخص حقیقی.
- مبالغ قطع (truncate) می‌شوند و گرد نمی‌شوند.

حتی کتابخانهٔ پایتونی که این اسکیل روی آن سوار شده ([`moadian-full`](https://pypi.org/project/moadian-full/) نسخهٔ ۰٫۰٫۲) چند مورد از همین‌ها را اشتباه پیاده کرده است. رقم کنترلی شمارهٔ مالیاتی‌اش هم در هیچ‌کدام از مثال‌های رسمی درست درنمی‌آید.

این اسکیل حدس زدن را حذف می‌کند:

- **مرجع‌های مستند:** معنی، نوع داده، مقادیر مجاز و فرمول هر فیلد به دستورالعمل رسمی *RC_IITP.IS_V7.8* (اردیبهشت ۱۴۰۵) یا یک منبع نام‌برده ارجاع دارد. هر چیزی که منبع نداشته باشد برچسب `[UNVERIFIED]` می‌خورد.
- **اسکریپت‌های قطعی:** بدون مدل زبانی کار می‌کنند. همه به‌جز یکی آفلاین‌اند و فقط به کتابخانهٔ استاندارد پایتون وابسته‌اند. سازنده و ارسال‌کننده به `moadian-full` هم نیاز دارند:

  | اسکریپت | کار |
  |---|---|
  | `scripts/validate_invoice.py` | ساختار، نوع داده، مقادیر مجاز، فیلدهای اجباری هر الگو، قواعد شرطی، محاسبات با قطع‌کردن و شمارهٔ مالیاتی را بررسی می‌کند و خروجی JSON خوانا (یا `--text`) می‌دهد. |
  | `scripts/build_invoice.py` | پوششی نازک روی `InvoiceBuilder` کتابخانهٔ moadian-full است. ورودی YAML/JSON ساده می‌گیرد، JSON صورتحساب می‌دهد و همهٔ خطاهای کتابخانه را اصلاح و فهرست می‌کند. |
  | `scripts/taxid.py` | شمارهٔ مالیاتی ۲۲ کاراکتری را با الگوریتم رسمی تولید، بررسی و تجزیه می‌کند. |
  | `scripts/explain_error.py` | معنی و راه رفع هر کد خطا را می‌دهد. اگر کد در فهرست نباشد، فقط ساختارش را رمزگشایی می‌کند. |
  | `scripts/send_invoice.py` | تنها اسکریپتی که به شبکه وصل می‌شود. فرمان `prepare` آفلاین است: صورتحساب را بررسی می‌کند و کد تأیید می‌دهد. فرمان `send --confirm <کد>` با کلاینت moadian-full امضا و ارسال می‌کند و باگ‌های ارسالِ آن کلاینت را هنگام اجرا اصلاح می‌کند. `inquiry` و `fiscal-info` فقط می‌خوانند. |

- **قواعد ایمنی:**
  - کلید خصوصی و گواهی فقط از مسیر فایل یا متغیر محیطی خوانده می‌شوند.
  - هیچ ارسالی بدون تأیید صریح کاربر انجام نمی‌شود.
  - اسکیل صریحاً می‌گوید که مشاورهٔ مالیاتی نیست.

## نصب

اسکریپت‌ها پایتون ۳٫۱۰ یا بالاتر لازم دارند. فقط `build_invoice.py` و `send_invoice.py` به کتابخانه نیاز دارند:

```bash
pip install moadian-full
```

**Claude Code (اسکیل شخصی)**

```bash
git clone https://github.com/googool2/moadian-invoice /tmp/moadian-invoice
cp -r /tmp/moadian-invoice/skills/moadian-invoice /tmp/moadian-invoice/skills/moadian-send ~/.claude/skills/
```

**Claude Code (از طریق plugin marketplace)**

```
/plugin marketplace add googool2/moadian-invoice
/plugin install moadian-invoice@moadian-invoice
```

**claude.ai:** یک فایل zip فقط با فایل‌های خود اسکیل بسازید و آن را در Settings › Capabilities › Skills بارگذاری کنید:

```bash
for s in moadian-invoice moadian-send; do
  git archive --format=zip --prefix=$s/ -o $s.zip HEAD:skills/$s
done
```

در محیط claude.ai اسکریپت‌های اعتبارسنجی، شمارهٔ مالیاتی و توضیح خطا بدون تغییر کار می‌کنند. سازنده فقط وقتی کار می‌کند که بشود آنجا `pip install moadian-full` را اجرا کرد.

**Codex:** پوشه را در پوشهٔ اسکیل‌های Codex کپی کنید. هر دو پوشهٔ `skills/moadian-invoice` و `skills/moadian-send` را در `~/.codex/skills/` کپی کنید. این مسیر از راهنماهای غیررسمی آمده؛ آن را با [مستندات Codex](https://developers.openai.com/codex/skills) تطبیق دهید.

## قبل و بعد

درخواست: «یه صورتحساب مودیان بساز: ۲ پرینتر هر کدوم ۱۲۰٬۰۰۰٬۰۰۰ ریال، ۴٬۰۰۰٬۰۰۰ ریال تخفیف روی ردیف، ارزش افزوده ۱۰٪، نقدی، خریدار حقوقی.»

**بدون اسکیل:** Claude فایل JSON را دستی نوشت. محاسبات درست بود، ولی در سرآمد `"cap": 259600000` (برابر tbill) و `"indati2m"` آمده بود. اعتبارسنج این را می‌گوید:

```
INVALID: 1 error(s), 2 warning(s)
  ERROR header.cap: cap is the cash amount EXCLUDING VAT and other taxes, so it cannot exceed
        tbill − tvam − todam (expected <= 236000000, found 259600000) — S1 §7-23
```

**با اسکیل:** Claude اسکریپت `build_invoice.py` را اجرا کرد و صورتحساب معتبر گرفت. گزارش نشان می‌دهد که moadian-full به‌تنهایی چه چیزی می‌فرستاد:

```
header.taxid   A1121605054000000001A6 -> A1121605054000000001A5   official check digit
body[0].dis    8000000 -> 4000000     dis is the line total; the library multiplied it by am
header.cap     255200000 -> null      cash amount excl. VAT; only for setm=3
header.insp    232000000 -> null      CREDIT amount; this is a cash invoice
validation: ok, 0 errors, 0 warnings
```

## ارزیابی

- **ارزیابی فعال‌شدن** (`evals/triggers.json`، ۵ پرامپتی که باید اسکیل را فعال کنند و ۵ پرامپتی که نباید، با `run_eval` از skill-creator و ۳ اجرا برای هر پرامپت): ۱۰ از ۱۰ درست. نتایج در `evals/results/` است. اجراها باید پشت سر هم باشند؛ اجرای موازی یک پوشهٔ مشترک دارد و فعال‌شدن را کمتر از واقع نشان می‌دهد.
- **ارزیابی سناریو** (`evals/outputs.json`): سه سناریو در دو دور، با اسکیل و بدون آن، با نشست‌های واقعی `claude -p` اجرا شد: ساخت صورتحساب، اشکال‌یابی نمونهٔ نامعتبر، و کلید خصوصی در چت همراه با «همین الان بفرست».
  - دور دوم با اسکیل: ۱۶ از ۱۶ معیار.
  - بدون اسکیل: ۷ از ۱۶ در دور اول و ۸ از ۱۲ در دور دوم. یک اجرای دور دوم به این مخزن دسترسی پیدا کرده بود و کنار گذاشته شد.
  - جزئیات در `evals/results/scenarios-2026-10-21.md` است.

## محدودیت‌ها

- **دسترسی به منابع:** فایل‌های PDF رسمی هنگام نوشتن از intamedia.ir در دسترس نبودند. آن‌ها از نسخه‌های عیناً کپی‌شده در یک مخزن عمومی GitHub خوانده شدند (هش‌ها در `references/fields.md` آمده است).
- **فیلدهای جدید:** فیلدهای نسخهٔ ۷٫۹ (`insr`، `nti1`، `nti2`، `hs`) تأییدنشده (`[UNVERIFIED]`) هستند.
- **کدهای خطا:** همهٔ کدهای `references/errors.md` از منابع ثانویه آمده‌اند: خلاصه‌های توسعه‌دهندگان از فهرست رسمی، راهنمای نرم‌افزارها و گزارش‌های محیط آزمایشی. آن‌ها را نشانهٔ قوی بدانید، نه متن رسمی.
- **بررسی ناقص:**
  - صورتحساب نوع سوم (رسید کارت‌خوان) فقط تا حدی بررسی می‌شود، چون جدول رسمی الزامات ستونی برای آن ندارد.
  - برخی فیلدهای «در شرایط خاص اجباری» (مثل سایر مالیات‌ها و جزئیات بارنامه) فهرست می‌شوند ولی خودکار بررسی نمی‌شوند.
- **داده‌های برخط بررسی نمی‌شوند:** وجود شناسهٔ کالا (`sstid`)، نرخ مالیات آن و شمارهٔ اقتصادی خریدار نیاز به استعلام برخط دارد و بررسی نمی‌شود.
- **رقم کنترلی شناسه‌ها:** فقط رقم کنترلی کد ملی ۱۰ رقمی و شناسهٔ ملی ۱۱ رقمی اشخاص حقوقی بررسی می‌شود.
  - الگوریتم از کتابخانه‌های متن‌باز آمده، نه از سند سازمان امور مالیاتی؛ برای همین ایراد آن فقط هشدار است.
  - کد فراگیر ۱۲ رقمی اتباع، شمارهٔ اقتصادی ۱۴ رقمی و شناسهٔ مشارکت مدنی بررسی نمی‌شوند.
- **ارسال:** فقط `send_invoice.py` امضا و ارسال می‌کند و برای این کار چهار چیز لازم دارد:
  - کد تأییدی که `prepare` برای همان فایل و همان مقصد صادر کرده باشد؛
  - کلیدهایی که فقط از متغیرهای محیطی خوانده شوند؛
  - برای سامانهٔ اصلی، `MOADIAN_ALLOW_LIVE=1` که خود کاربر تنظیم کرده باشد؛
  - برای sandbox، آدرسی که کاربر بدهد؛ سند رسمی آدرس sandbox ندارد و اسکیل هم آدرسی ارائه نمی‌کند.

  مسیر ارسال فقط با یک سرور ساختگی آزمایش شده و هنوز روی sandbox یا سامانهٔ واقعی اجرا نشده است. راهنما در `skills/moadian-send/references/sending.md` است.
- **مجوز:** مجوز `moadian-full` از نوع GPL-3.0 است. این اسکیل MIT است و آن کتابخانه را در خودش ندارد؛ فقط هنگام اجرا آن را import می‌کند.
- **مشاورهٔ مالیاتی نیست:** اسکیل فقط قالب و محاسبات را با اسناد سازمان امور مالیاتی تطبیق می‌دهد. مشمول بودن معامله یا نرخ درست را تعیین نمی‌کند.
